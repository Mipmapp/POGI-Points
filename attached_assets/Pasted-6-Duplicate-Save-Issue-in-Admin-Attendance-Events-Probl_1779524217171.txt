6. Duplicate Save Issue in Admin > Attendance > Events

Problem:
When editing a session in:

Admin > Attendance > Events

and clicking Save Changes multiple times (or reopening and saving again), the system creates duplicate saves/duplicate records instead of updating the existing session once.

Expected behavior:

editing should UPDATE the existing session
repeated saves should not create duplicates
only one valid save operation should occur per action

Investigate deeply:

frontend submit handlers
duplicate form submissions
multiple event listeners
React re-render side effects
async save race conditions
modal lifecycle issues
optimistic UI logic
backend PUT/PATCH handling
database upsert/update logic
duplicate API requests
websocket event duplication if applicable

Check for:

missing debounce/throttle
button not disabling during submit
stale state resubmission
duplicated onClick and onSubmit
duplicated API mutation hooks
repeated socket emissions
modal remount issues
improper React StrictMode effects

Required fixes:

ensure save executes only once per action
disable save button while request is processing
prevent duplicate requests
use proper update/upsert logic instead of insert
ensure idempotent backend updates
add request locking if needed

Also:

verify edits persist correctly after refresh
ensure no duplicate session entries exist in database
safely clean existing accidental duplicates if detected

Recommended implementation:

use PATCH/PUT for edits
add isSaving state guard
add backend uniqueness validation
return updated entity instead of creating a new one

Example frontend protection:

disable submit button during pending request
prevent rapid double-click saves
ignore duplicate submissions until completion

This issue strongly suggests:

duplicated frontend handlers OR
backend “create instead of update” logic OR
modal state duplication from rerenders.

It’s a very common React/admin dashboard issue, especially in systems with modals and async mutations
