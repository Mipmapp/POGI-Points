7. Audit Trail Missing User Names and Action Details

Investigate why the Audit Trail across the entire system does NOT properly display:

Treasurer names
Admin names
Staff names
Actor/user identity
Detailed action descriptions

Currently, audit logs may only show:

incomplete records
blank actor fields
missing names
generic actions
missing metadata/details

This must be fixed system-wide.

Deep Investigation Required

Trace the FULL audit logging flow:

Frontend Action
→ API Request
→ Authentication/User Session
→ Backend Controller/Service
→ Audit Logger
→ Database Storage
→ Audit Trail UI Rendering

Identify where actor/user information is lost.

Check These Possible Root Causes
Authentication Context Issues

Verify:

session contains authenticated user data
JWT/session tokens properly decode user identity
middleware attaches user info correctly
backend requests receive authenticated actor

Check if:

req.user
session.user
auth.user
or equivalent context

is missing during audit creation.

Audit Log Schema Problems

Inspect database schema/model.

Verify audit records store:

actor ID
actor name
actor role
action type
affected entity
entity ID
timestamps
change details
before/after values if applicable

Possible issue:

audit table only stores IDs
missing joins/population
actorName field missing
relations not connected
Backend Audit Service Issues

Inspect:

audit logger utility/service
middleware
mutation handlers
event handlers

Check whether:

audit logs are created before auth context exists
actor data is not passed into logger
logger uses null fallback values
async operations lose request context
UI Rendering Issues

Inspect audit trail frontend.

Verify:

actor names are fetched correctly
relational data is populated
API returns complete actor information
frontend table/cards display actor names properly

Check for:

null rendering
missing joins/includes
incorrect field mapping
stale cached data
Improve Audit Logging System-Wide

Enhance audit trail architecture to include:

Actor Information
full name
role
email/username if needed
profile/avatar optional
Detailed Actions

Examples:

“Treasurer John Doe updated Event Contribution Amount”
“Admin Jane Smith approved attendance session”
“Staff updated member profile”
“User checked in to event”

Avoid vague logs like:

“Updated record”
“Changed data”
Capture Rich Metadata

Where possible, store:

affected module/page
entity type
entity ID
old values
new values
timestamps
IP/device optional
source platform (mobile/admin/POS)
Ensure System-Wide Coverage

Audit logging should work consistently for:

attendance
contributions
POS
events
sessions
dashboard actions
approvals
profile updates
settings
admin actions
treasurer actions
Requirements
avoid duplicate audit entries
prevent performance degradation
avoid exposing sensitive/private fields
ensure logs remain readable
maintain scalability
Final Deliverables

After fixing:

summarize root cause
summarize modified audit architecture
summarize database changes
summarize improved logging coverage
list all areas now properly tracked
